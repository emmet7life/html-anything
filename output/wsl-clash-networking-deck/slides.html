03 / 08
TWO NETWORK WORLDS

Windows 与 WSL 并不是同一个网络现场

01Windows
Clash Verge 常开
浏览器、Windows 应用和部分 TUN 流量可以正常接管。
  • HTTP/Mixed Port 监听 7890 / 7897
  • 规则模式决定流量出口
  • Allow LAN 决定 WSL 是否可连
02WSL2
CLI 工具独立运行
git、curl、pip、pnpm 不会自动继承 Windows 浏览器代理。
  • 默认网关可能重启后变化
  • 环境变量必须显式设置
  • 排查时要区分代理与直连
DECISION · Treat WSL as a separate client, not a Windows browser tab.

CONFIG SPEC
05 / 08
SHELL RC

把代理写成动态环境

export WIN_HOST="$(ip route | awk '/^default/ {print $3; exit}')"
export HTTP_PROXY="http://${WIN_HOST}:7890"
export HTTPS_PROXY="$HTTP_PROXY"
export ALL_PROXY="$HTTP_PROXY"
WHY DYNAMIC

WSL 默认网关会变，代理地址不能硬编码。

NO_PROXY

本地、内网、WSL-to-Windows 直连服务要绕过代理。

SOURCE

写进 ~/.bashrc 或 ~/.zshrc 后重新 source。

CONFIGURATION · one shell, many tools.

NPM / PNPM

TAKEAWAYS
03 RULES
01

WSL 是独立客户端

不要假设 Windows 浏览器能访问，WSL CLI 就能访问。

02

代理地址动态生成

用默认网关拼出 HTTP_PROXY，避免重启后失效。

03

直连排查必须绕过代理

`--noproxy '*'` 是区分服务问题和代理问题的关键。
